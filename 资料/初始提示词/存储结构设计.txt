# 图片+文本混合内容——存储、上传与跨端渲染提示词

## 一、数据库 Schema 与后端 API 设计
（此部分由后端实现，但前端需知晓接口格式，请生成接口说明与示例）

### 1.1 数据库表设计
- 使用 PostgreSQL，图片文件存储于对象存储（如阿里云 OSS），数据库仅保存元数据和 URL。
- **notes 表**：
  - id: uuid (PK)
  - user_id: uuid (FK -> users)
  - title: varchar(255)
  - content: jsonb   // Block-based JSON 数组，例如 [ { type: "heading", text: "标题" }, { type: "image", url: "https://cdn...", thumb_url: "...", width: 800, height: 600 } ]
  - plain_text: text  // 从 content 中提取所有文本拼接，用于全文搜索
  - created_at, updated_at: timestamptz
- **images 表**：
  - id: uuid (PK)
  - user_id: uuid (FK)
  - original_url: text (对象存储原图 URL)
  - thumb_url: text (缩略图 URL)
  - width: int
  - height: int
  - size: int (bytes)
  - uploaded_at: timestamptz
- 索引：在 notes 的 plain_text 字段上创建 GIN 索引，用于全文检索；images.user_id 建立索引。

### 1.2 RESTful API 格式（前端调用参考）
所有接口需附带 JWT 认证头：
```
Authorization: Bearer <token>
```

#### a. 创建笔记
- **POST** `/notes`
- Request body:
```json
{
  "title": "我的笔记",
  "content": [
    { "type": "heading", "text": "标题" },
    { "type": "image", "url": "https://cdn.example.com/img1.jpg", "thumb_url": "https://cdn.example.com/img1_thumb.jpg", "width": 800, "height": 600 }
  ]
}
```
- Response (201):
```json
{
  "id": "uuid",
  "title": "我的笔记",
  "content": [...],
  "plain_text": "标题\n",
  "created_at": "...",
  "updated_at": "..."
}
```

#### b. 获取笔记详情
- **GET** `/notes/:id`
- Response:
```json
{
  "id": "uuid",
  "title": "...",
  "content": [...],
  "plain_text": "...",
  "created_at": "...",
  "updated_at": "..."
}
```

#### c. 更新笔记内容
- **PUT** `/notes/:id`
- Request body 同创建，但部分更新亦可接受（此处为简化，全量替换 content）。
- 后端需根据传入 content 重新生成 plain_text。
- Response 返回更新后的完整笔记对象。

#### d. 上传图片
- **POST** `/upload`
- Content-Type: multipart/form-data
- 字段：`file` (图片文件)
- Response (200):
```json
{
  "id": "uuid",
  "original_url": "https://cdn.../original.jpg",
  "thumb_url": "https://cdn.../thumb.jpg",
  "width": 1920,
  "height": 1080,
  "size": 204800
}
```

#### e. 获取图片列表
- **GET** `/images?offset=0&limit=20`
- Response:
```json
{
  "data": [
    {
      "id": "uuid",
      "original_url": "...",
      "thumb_url": "...",
      "width": ...,
      "height": ...,
      "uploaded_at": "..."
    }
  ],
  "total": 100
}
```

## 二、前端图片上传服务与组件（Taro 跨端）

### 2.1 图片上传服务（src/services/upload.ts）
需要封装一个统一的异步函数，处理图片选择和上传的完整流程，并兼容 Android、微信小程序、H5 环境。
- 函数签名：
```ts
function chooseAndUpload(options?: {
  count?: number;         // 最多选择图片数量
  sourceType?: Array<'album' | 'camera'>;
}): Promise<UploadedImage[]>
```
- 内部逻辑：
  1. 调用 `Taro.chooseImage` 选择图片，获取临时路径数组。
  2. 遍历临时路径，依次调用 `Taro.uploadFile`，将文件上传到 `/upload` 接口。
  3. 上传时在 header 中附带 JWT token。
  4. 返回上传后服务端返回的图片信息数组（url、thumb_url、width、height 等）。
  5. 处理错误：网络异常、用户取消选择等，均通过 Promise reject 抛出，调用方自行捕获。
  6. **平台差异处理**：
     - 微信小程序：`Taro.chooseImage` 需注意 count 限制，返回的 tempFilePaths 可直接用于上传；图片域名需在微信后台配置。
     - Android：需要在 app 中申请读写存储权限（此处仅添加注释，不实现原生权限申请代码，提示开发者需在 AndroidManifest.xml 中声明）。
     - H5：`Taro.chooseImage` 会调用浏览器 File API，上传使用 `XMLHttpRequest` 或 fetch，注意跨域配置。

### 2.2 图片上传按钮组件（src/components/UploadImageButton）
- Props：
  - `onUploaded: (images: UploadedImage[]) => void`（上传成功回调）
  - `multiple?: boolean`（是否允许多选）
  - `disabled?: boolean`
- 组件内部：
  - 渲染一个按钮（可自定义子元素，默认显示“上传图片”）。
  - 点击按钮触发 `chooseAndUpload`，显示 loading 状态。
  - 上传成功后调用 `onUploaded` 并清除 loading。
  - 上传失败时使用 `Taro.showToast` 提示错误。
- 注意：
  - 组件不负责图片的展示，仅负责选择和上传，业务方在回调中决定如何插入到 content blocks 中。
  - 为避免小程序端频繁弹出授权，可在组件内做防抖处理。

## 三、富文本内容渲染组件（跨端通用）

### 3.1 组件定义（src/components/NoteContentRenderer）
- Props:
  - `content: ContentBlock[]`  // ContentBlock 为联合类型，包含不同 block 的 type
  - `emptyText?: string`（无内容时的占位文本，默认“暂无内容”）
  - `onError?: (block: ContentBlock, error: any) => void`（图片加载错误回调）
- 类型定义（ContentBlock）：
```ts
type ContentBlock = 
  | { type: 'heading'; text: string; level?: 1 | 2 | 3 }
  | { type: 'paragraph'; text: string }
  | { type: 'image'; url: string; thumb_url?: string; width?: number; height?: number; alt?: string }
  | { type: 'other'; data: any }; // 预留扩展
```
- 渲染逻辑：
  - 循环遍历 `content` 数组，根据 `type` 渲染对应组件：
    - `heading`：使用 `Taro.View` 包裹 `Taro.Text`，根据 level 设置字体大小。
    - `paragraph`：普通 `Text` 组件。
    - `image`：使用 `Taro.Image`，`src` 优先使用 `thumb_url` 或 `url`，设置 `mode="widthFix"` 或保持原始比例，并设置 `lazy-load`；在加载错误时显示占位图（本地 assets 中的占位图）。
    - `other`：预留一个 `View`，可由外部通过插槽或 render props 自定义渲染（初期可简单渲染 `JSON.stringify(data)`）。
  - 注意小程序的图片域名白名单：需提示配置 `https://cdn.example.com` 等域名。
  - 组件应保持纯展示，无状态，性能优化可使用 `React.memo`。

## 四、流转触发与接收处理

### 4.1 发送流转
在笔记编辑页面，添加“流转到其他设备”按钮。
- 点击后：
  1. 从 Zustand 的 `noteStore` 获取当前编辑的 content 数组（注意图片URL已含在 block 中，无需额外处理）。
  2. 调用 `transferService.sendTransferTo(targetDevice, 'NOTE_CONTENT', { noteId, content, title })`。
  3. 目标设备选择：可复用之前设备列表弹窗，或简化为“发送到我的其他设备”（广播模式，服务端负责发送给所有该用户的其他在线设备）。

### 4.2 接收流转
- 在 `transferService` 中，当收到 `server:stateUpdate` 事件且 `action === 'NOTE_CONTENT'` 时：
  - 将 payload 中的 content、noteId 等存入 `transferStore` 的 `incomingTransfer`。
  - 当前笔记编辑页面监听 `transferStore` 的变化，当检测到 `incomingTransfer` 匹配当前笔记（或新笔记）时，弹出提示：“收到来自XX设备的笔记内容，是否覆盖当前编辑内容？”。
  - 用户确认后，将 content 设置到 `noteStore` 中，并刷新 `NoteContentRenderer`。
  - 如果接收时当前不在编辑页面，可仅弹通知，待用户进入编辑页时自动应用（根据 product 需求决定）。
- 过渡动画：使用 `Taro.showToast` 或一个自定义 Modal 提供简单的提示。

## 五、完整笔记编辑页面（pages/note/edit.tsx）

### 5.1 页面状态管理
新建 `src/stores/useNoteStore.ts`：
```ts
interface NoteState {
  noteId: string | null;
  title: string;
  content: ContentBlock[];
  isDirty: boolean;
  // actions
  setNoteId: (id: string) => void;
  setTitle: (title: string) => void;
  setContent: (content: ContentBlock[]) => void;
  addBlock: (block: ContentBlock) => void;
  updateBlock: (index: number, block: ContentBlock) => void;
  removeBlock: (index: number) => void;
  loadNote: (noteId: string) => Promise<void>;   // 调用 GET /notes/:id
  saveNote: () => Promise<void>;                 // 调用 POST/PUT /notes
  reset: () => void;
}
```
- `saveNote` 内部需构建 plain_text 发送（但为简化，可让后端自动生成，前端只传 content）。
- 确保 store 与流转系统解耦，通过页面手动触发流转。

### 5.2 编辑页面布局
- 顶部：标题输入框。
- 中间：可滚动的内容区，每一块内容为可编辑的单元（文本块可点击编辑、图片块显示缩略图并提供删除按钮）。
- 底部工具栏：
  - “添加文本块”按钮：在 content 末尾新增一个 `{ type: 'paragraph', text: '' }`，并聚焦编辑。
  - `<UploadImageButton>`：上传图片后，将返回的图片信息构造成 `type: 'image'` 的 block，追加到 content 末尾。
  - “保存”按钮。
  - “流转”按钮（只有内容非空时激活）。
- 预览模式：可切换纯文本/图片的只读预览，使用 `NoteContentRenderer` 渲染。
- 页面退出时，如果有未保存内容，提示用户（使用 `Taro.showModal`）。

### 5.3 流转按钮逻辑
- 获取当前 `noteStore.content`，调用 `transferService.sendTransferTo('broadcast', 'NOTE_CONTENT', { content, title })` 或选择特定设备。
- 流转成功后 Toast 提示“内容已发送”。
