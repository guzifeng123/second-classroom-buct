# 项目目标
创建一个多端统一的应用，支持 **Android App、微信小程序、Web(H5)** 三个平台，
所有平台共享同一套业务代码，并支持“多端流转”（同一账号在不同设备间无缝接续使用状态，例如手机编辑的内容在电脑上立刻继续）。

# 技术栈与工具
- 前端跨端框架：Taro 3.x + React + TypeScript
- Android 端渲染方式：React Native（Taro 的 RN 模式）
- 微信小程序：Taro 编译为原生小程序代码
- Web：Taro 编译为 React SPA（H5）
- 状态管理：Zustand（轻量、跨端无痛）
- 网络请求：统一封装 axios / Taro.request
- 实时通信：WebSocket（长连接），使用 socket.io-client 或原生 WebSocket
- 后端（本次提示词仅前端部分，但需预留接口）：
  - REST API 用于普通业务
  - WebSocket 房间按用户 ID 分组，用于多端状态同步
  - Redis 保存用户会话状态快照

# 核心要求
1. **一套代码覆盖三端**，利用 Taro 的条件编译处理极少量平台差异。
2. **状态管理完全共享**，登录后的用户信息、业务数据、流转状态均通过 Zustand 统一管理。
3. **所有端使用同一套 WebSocket 管理逻辑**：
   - 用户登录后，WebSocket 连接到后端房间（room = 用户ID）
   - 前端实时监听其他端发来的状态更新，并自动 merge 到本地 Zustand store
   - 用户主动触发流转时，通过 WebSocket 发送“流转意图”给服务端，服务端广播到其他端
4. **优雅的离线与重连机制**：
   - WebSocket 断线自动重连
   - 上线后自动拉取最新状态快照（API 调用）
5. **目录结构清晰**，反映跨端复用的分层：
   - src/pages 业务页面（跨端共享）
   - src/components 跨端组件
   - src/stores Zustand store
   - src/services API 和 WebSocket 封装
   - src/utils 工具函数
   - platform/ 平台特有代码（极少，用 Taro 条件编译文件）
